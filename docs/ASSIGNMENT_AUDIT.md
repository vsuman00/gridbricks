## Vercel and Docker delivery path

Use one Vercel container for this small assignment app. [Vercel supports `Dockerfile.vercel`](https://vercel.com/kb/guide/does-vercel-support-docker-deployments) at the project root and builds it into a request-driven Function. That gives the assignment a real Docker build without splitting the app into two Vercel projects. The image must serve HTTP on `$PORT`. [Container Functions are stateless](https://vercel.com/kb/guide/does-vercel-support-docker-deployments); do not treat a runtime SQLite write as a durable import. Vercel does not deploy Docker Compose files.

1. **Container prepared:** The multi-stage [`Dockerfile.vercel`](../Dockerfile.vercel) builds the locked frontend and backend, copies the Vite output, and starts FastAPI on `0.0.0.0:$PORT`. The same-origin UI and `/api/v1` run in one process. The local two-server workflow remains available.
2. **Data packaged:** [`deployment/data/`](../deployment/data/) contains the reviewed live January SQLite snapshot, manifest and 69 raw source responses. The build checks the database, snapshot ID, input hash, manifest and every raw hash. Runtime files are read-only; browser requests do not import. A later refresh requires a new reviewed image and deployment, or a separately designed durable store.
3. **Public entry prepared:** The deployed mode serves the built UI at `/`, accepts Vercel's generated and production Host values, and applies separate UI/API security policies. Local container checks passed; actual Vercel ingress remains untested.
4. **Docker tested locally:** `docker build -f Dockerfile.vercel -t gridbricks-vercel:assignment .` and `docker run --rm -p 127.0.0.1:4286:8000 -e PORT=8000 gridbricks-vercel:assignment` completed. UI, asset, health, Decision, Accuracy, CSV and a browser view check passed. The image ran as UID 10001 and the snapshot was not writable by that user.
5. **Deploy on Vercel:** Import the [public repository](https://github.com/vsuman00/gridbricks) root into a Vercel project. Vercel will detect `Dockerfile.vercel`; deploy the production branch. Review build and Function logs and use the resulting production URL, not an authenticated preview link.
6. **Release check:** In a signed-out private browser window, open the production home page, change the 15 January cutoff, load a January Accuracy range, download CSV, refresh a pinned URL and check both desktop and mobile layout. Confirm the snapshot and metrics match the packaged data. Then place the production URL in the README and form.

The [Vercel container guide](https://vercel.com/kb/guide/does-vercel-support-docker-deployments) and [deployment protection guide](https://vercel.com/docs/deployment-protection) support the Docker and public-access checks. The public Host and static-serving changes are implemented and tested locally; hosted verification remains required. Local results cannot certify Vercel behavior.
